# Data Model: Business Trip Management

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Research**: [research.md](./research.md)

Storage: PostgreSQL 17, schema managed by Flyway. All points in time are stored as
`timestamptz` (UTC) and converted from/to Europe/Berlin at the web boundary (research R4).

```text
┌──────────────┐ 1        0..* ┌────────────────────────┐ 0..*      1 ┌──────────────────────┐
│ car          │───────────────│ business_trip          │─────────────│ User (OIDC identity) │
│ (3 rows)     │               │                        │ owner_subject│ not persisted        │
└──────────────┘               └────────────────────────┘             └──────────────────────┘
```

---

## Car

One of exactly three pool vehicles. Reconciled from configuration at startup (research R8);
no user can create, change or delete cars (FR-002).

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| `id` | `smallint` | PK, `CHECK (id BETWEEN 1 AND 3)` | Stable slot number; configuration index 0–2 maps to id 1–3 |
| `display_name` | `varchar(80)` | NOT NULL, not blank | e.g. "VW ID.3 (blau)" (FR-003) |
| `license_plate` | `varchar(15)` | NOT NULL, UNIQUE | e.g. "H-LG 1234" (FR-003) |

**Validation (startup)**: exactly three cars configured; names and plates non-blank; plates
unique. Otherwise the application refuses to start.

**Derived, not stored — Availability**: for a requested period `[start, end)` a car is
*not available* if a business trip exists with the same `car_id` whose period overlaps,
ignoring the trip currently being edited (FR-004a, FR-020). Only the boolean is exposed
(FR-019).

## BusinessTrip

A single trip recorded by one user for one car.

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| `id` | `uuid` | PK, generated by the application | Random UUID; not guessable (defence in depth, ownership is still checked) |
| `owner_subject` | `varchar(255)` | NOT NULL | `iss` + `sub` of the OIDC identity (FR-009); no name, e-mail or other personal data (data minimization) |
| `car_id` | `smallint` | NOT NULL, FK → `car.id` `ON DELETE RESTRICT` | FR-005 |
| `start_at` | `timestamptz` | NOT NULL | FR-005 |
| `end_at` | `timestamptz` | NOT NULL, `CHECK (end_at > start_at)` | FR-006 |
| `destination` | `varchar(200)` | NOT NULL, `CHECK (char_length(btrim(destination)) BETWEEN 1 AND 200)` | Stored trimmed (FR-007) |
| `created_at` | `timestamptz` | NOT NULL, default `now()` | "Time of recording"; tiebreaker for sorting |
| `updated_at` | `timestamptz` | NOT NULL | Set on every change |
| `version` | `integer` | NOT NULL, default 0 | Optimistic locking (research R5) |

**Constraints & indexes**

```sql
-- FR-017 / FR-018 / SC-007: no overlapping periods per car, back-to-back allowed
EXCLUDE USING gist (car_id WITH =, tstzrange(start_at, end_at, '[)') WITH &&)

-- FR-011 / SC-003: list view per user
CREATE INDEX business_trip_owner_start_idx
  ON business_trip (owner_subject, start_at, created_at, id);

-- FR-024: retention job
CREATE INDEX business_trip_end_idx ON business_trip (end_at);
```

**Sort order (FR-011, edge case "identical start")**: `start_at ASC, created_at ASC, id ASC`.

### Validation rules (server side, FR-008)

Checked in this order when leaving a wizard step and again when saving. Every rule has a
German message that states what went wrong and what to do (FR-010, Principle I).

| # | Rule | Source | Step | Message key (example text) |
|---|------|--------|------|----------------------------|
| V1 | Start date, start time, end date, end time present | FR-005 | Period | `trip.start.required` ("Bitte geben Sie das Startdatum an.") |
| V2 | Values parse as date / time | FR-008 | Period | `trip.date.invalid` ("Bitte geben Sie ein gültiges Datum an.") |
| V3 | `end_at > start_at` | FR-006 | Period | `trip.end.notAfterStart` ("Das Ende muss nach dem Beginn liegen.") |
| V4 | `start_at > now` (server clock) | FR-006a | Period **and** Save | `trip.start.notInFuture` ("Dienstreisen können nur mit einem Beginn in der Zukunft gebucht werden. Bitte wählen Sie einen späteren Beginn.") |
| V5 | Car selected, exists (id 1–3) | FR-005 | Car | `trip.car.required` ("Bitte wählen Sie ein Fahrzeug aus.") |
| V6 | Selected car is available for the period (excluding the trip being edited) | FR-004a, FR-017 | Car **and** Save | `trip.car.booked` ("Dieses Fahrzeug ist im gewählten Zeitraum bereits gebucht. Bitte wählen Sie ein anderes Fahrzeug oder einen anderen Zeitraum.") |
| V7 | Destination trimmed not empty | FR-005, FR-007 | Destination | `trip.destination.required` ("Bitte geben Sie das Reiseziel an.") |
| V8 | Destination ≤ 200 characters, no control characters | FR-007 | Destination | `trip.destination.tooLong` ("Das Reiseziel darf höchstens 200 Zeichen lang sein.") |
| V9 | (Edit/Delete) trip belongs to current user | FR-013, FR-022 | Any | → HTTP 404, generic "Dienstreise nicht gefunden." |
| V10 | (Edit/Delete) stored `start_at > now` | FR-023 | Any | `trip.readOnly` ("Diese Dienstreise hat bereits begonnen und kann nicht mehr geändert oder gelöscht werden.") |
| V11 | (Edit) `version` matches | R5 | Save | `trip.staleEdit` ("Die Dienstreise wurde zwischenzeitlich geändert. Bitte laden Sie sie neu.") |

If all cars are unavailable, the car step shows `trip.car.noneAvailable`
("Für diesen Zeitraum ist kein Fahrzeug frei. Bitte ändern Sie Beginn oder Ende.") (US1 AS4).

### State model

A trip's state is **derived** from the server clock; it is not stored.

```text
             create (V1–V8)
                  │
                  ▼
   ┌──────────────────────────┐   edit (V1–V11)  ┌───────────┐
   │ UPCOMING  now < start_at │◄────────────────►│ (same)    │
   └──────────────────────────┘                  └───────────┘
        │               │ delete (confirmed, V9, V10)
        │               ▼
        │          [removed permanently, slot freed]
        │ now ≥ start_at
        ▼
   ┌──────────────────────────┐
   │ ONGOING  start ≤ now < end│   read-only (FR-023)
   └──────────────────────────┘
        │ now ≥ end_at
        ▼
   ┌──────────────────────────┐
   │ PAST                     │   read-only
   └──────────────────────────┘
        │ now ≥ end_at + retention (FR-024)
        ▼
   [deleted by retention job]
```

The list view shows "Bearbeiten"/"Löschen" only for `UPCOMING`, and a status label
("Geplant", "Läuft", "Abgeschlossen") for every entry.

## User (not persisted)

Provided by the OIDC login per session.

| Attribute | Source | Use |
|-----------|--------|-----|
| subject | `iss` + `sub` claims | Ownership key stored on each trip |
| display name | `name` / `preferred_username` claim | Shown in page header only, never stored |

All users have the same single role (FR-001a).

---

## Session (infrastructure)

Spring Session JDBC tables (`spring_session`, `spring_session_attributes`), created by
Flyway. They hold the security context only; wizard progress is carried in the forms, not
in the session (see [contracts/ui-routes.md](./contracts/ui-routes.md)). Expired sessions are
purged by Spring Session.
